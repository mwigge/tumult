Resilience control panel

A role-aware UI over the tumult-mcp server — every action is an MCP tools/call. Author an experiment, run a fault, then read the results as analytics, compliance evidence, and the ChaosGraph. The panel enforces the same viewer/operator tiers the server does (defense in depth); the server still enforces regardless of what the UI shows.

Sections

Author scaffolds a validated experiment (read-only). Run injects faults and drives the full loop (operator only). Analytics, Compliance and ChaosGraph read accumulated history (read-only).

Author a new experiment

Pick a fault from the live catalog, fill its arguments and a steady-state probe, and Tumult scaffolds a validated .toon. This is read-only — tumult_scaffold_experiment generates and validates but never runs — so viewers can use it too.

The same authoring path tumult new and an agent drive, over tools/call. The demo mounts experiments read-only, so copy the generated TOON and run it with tumult run <file>.

Fault domains

          
One experiment per domain. Each injects a real fault, then verifies recovery —
            a passing run is a resilience result, not a smoke-test tick. Run one, then follow its trace link.

          


          
Safety guardrail

          
Not every run should finish. This experiment arms an auto-halt guard that watches
            the target during a database outage and pulls the run — running rollback — the instant it turns unhealthy.
            Expected outcome: Halted, not Completed.
